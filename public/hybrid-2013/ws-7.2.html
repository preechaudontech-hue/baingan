ใบงานที่ 7.2 ส่ง แก้ไข และลบข้อมูลผ่าน API

เวลา 120 นาที · งานเดี่ยว · คะแนนเต็ม 10

จุดประสงค์

เรียก API ด้วยเมธอด POST PATCH และ DELETE พร้อมจัดการผลและข้อผิดพลาด และอัปเดตหน้าจอให้สอดคล้องกับผลที่ได้

คำชี้แจง

สร้างหน้าจัดการโพสต์ที่ดึงรายการ เพิ่ม แก้ไข และลบ ผ่าน JSONPlaceholder (API จำลองที่ไม่บันทึกข้อมูลจริง) โดยเติมฟังก์ชันที่เป็น TODO ในไฟล์ posts.ts แล้วเชื่อมกับหน้าจอ

สิ่งที่ต้องเตรียม

  • ผลงานใบงาน 7.1 และ 4.2 - 4.3
  • ใบความรู้ที่ 7 หัวข้อ ส่ง แก้ไข และลบข้อมูล
  • ไฟล์ src/api/http.ts

โค้ดตั้งต้น

คัดลอกไปวางในไฟล์ที่ระบุในโค้ด
// src/api/posts.ts
import { getJson, sendJson } from './http';

export interface Post { id: number; userId: number; title: string; body: string }

const BASE = 'https://jsonplaceholder.typicode.com';

export const listPosts = (signal?: AbortSignal) => getJson<Post[]>(`${BASE}/posts?_limit=10`, signal);

export const createPost = (title: string, body: string) =>
  sendJson<Post>('POST', `${BASE}/posts`, { title, body, userId: 1 });

export async function updatePost(id: number, changes: Partial<Post>): Promise<Post> {
  // TODO: ส่ง PATCH ไปที่ `${BASE}/posts/${id}` ด้วย sendJson แล้วคืนโพสต์ที่ได้
  throw new Error('ยังไม่ได้เขียน updatePost ' + id + JSON.stringify(changes));
}

export async function deletePost(id: number): Promise<void> {
  // TODO: ส่ง DELETE ไปที่ `${BASE}/posts/${id}` ด้วย sendJson
  throw new Error('ยังไม่ได้เขียน deletePost ' + id);
}

ขั้นตอนการปฏิบัติ

  1. สร้างไฟล์ src/api/posts.ts จากโค้ดตั้งต้น แล้วเติมฟังก์ชัน updatePost (PATCH) และ deletePost (DELETE) ตามคอมเมนต์

  2. สร้างหน้ารายการโพสต์ ใช้ useEffect เรียก listPosts พร้อมยกเลิกคำขอเมื่อออกจากหน้า (AbortController) และมีสถานะกำลังโหลด ผิดพลาด ว่าง

  3. เพิ่มฟอร์มสร้างโพสต์ (ชื่อเรื่อง เนื้อหา) ที่ตรวจข้อมูลก่อนส่ง ปิดปุ่มขณะรอคำตอบ แล้วเพิ่มโพสต์ที่ได้ไว้บนสุดของรายการ (JSONPlaceholder ตอบ id 101 เสมอ ให้ใช้ id ชั่วคราวฝั่งแอปสำหรับ key ไม่ให้ซ้ำ)

  4. เพิ่มการแก้ไขชื่อเรื่องด้วย PATCH และอัปเดตรายการในหน้าจอจากคำตอบ

  5. เพิ่มการลบด้วย DELETE พร้อมกล่องถามยืนยัน (useIonAlert) แล้วลบรายการออกจากหน้าจอเมื่อสำเร็จ

  6. ทดสอบความผิดพลาด: ปิดอินเทอร์เน็ตแล้วกดสร้างและลบ ดูว่าหน้าจอไม่เปลี่ยนผิดและแจ้งผู้ใช้อย่างเข้าใจ จากนั้นเรียกโพสต์ที่ไม่มีอยู่ (เช่น /posts/9999) ตรวจว่าได้ 404 และแอปแสดงข้อความ ถ่ายภาพ

  7. เขียนตาราง 3 แถว (สร้าง แก้ไข ลบ): เมธอด URL เนื้อหาที่ส่ง รหัสสถานะที่ได้ (ดูจากแท็บ Network) และข้อความที่ผู้ใช้เห็น

  8. รีเฟรชหน้าแล้วดูว่ารายการที่สร้างหายไป อธิบายเหตุผล (อ้างอิงข้อจำกัดของ JSONPlaceholder) และอธิบายว่า API จริงของแอปที่มีฐานข้อมูลจะต่างอย่างไร

คำแนะนำ

  • ถ้า PATCH หรือ DELETE ถูกบล็อก ให้ตรวจว่าใช้ HTTPS และพิมพ์ URL ถูก
  • ปิดปุ่มขณะรอคำตอบเพื่อกันการกดซ้ำ แล้วเปิดปุ่มคืนใน finally
  • การแก้ state ของรายการต้องสร้างอาร์เรย์ใหม่ด้วย map หรือ filter

สิ่งที่ต้องส่ง

ลิงก์ GitHub + ภาพหน้าจอ (รายการ ฟอร์มกรอกผิด และกรณีออฟไลน์) + ตาราง 3 แถวพร้อมภาพแท็บ Network + คำอธิบายข้อ 8 (ส่งตามช่องทางที่ครูกำหนด)
