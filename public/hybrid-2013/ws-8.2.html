ใบงานที่ 8.2 ประเมินคุณภาพและปรับปรุงการเข้าถึงของแอป

เวลา 150 นาที · งานเดี่ยว · คะแนนเต็ม 10

จุดประสงค์

ประเมินคุณภาพของแอปตนเองตามมาตรฐานและด้วย Lighthouse และปรับปรุงการเข้าถึงได้ พร้อมหลักฐานก่อนและหลัง

คำชี้แจง

ฝึกแก้ปัญหาการเข้าถึงจากฟอร์มตัวอย่างที่มีปัญหา เขียนการทดสอบที่พิสูจน์ว่าแก้แล้ว จากนั้นประเมินและปรับปรุงแอปของตนเอง

สิ่งที่ต้องเตรียม

  • ผลงานใบงาน 8.1
  • ใบความรู้ที่ 8 หัวข้อคุณภาพและการเข้าถึง
  • Chrome (สำหรับ Lighthouse)

โค้ดตั้งต้น

คัดลอกไปวางในไฟล์ที่ระบุในโค้ด
import { useState } from 'react';

// ฟอร์มนี้มีปัญหาด้านการเข้าถึงอย่างน้อย 5 จุด ให้ค้นหาและแก้ไข
const BadForm: React.FC = () => {
  const [title, setTitle] = useState('');
  const [items, setItems] = useState<string[]>([]);

  function add() {
    if (title.trim() === '') return;
    setItems([...items, title.trim()]);
    setTitle('');
  }

  return (
    <div>
      <div style={{ fontSize: 24 }}>รายการของฉัน</div>

      <input placeholder="ชื่อรายการ" value={title} onChange={e => setTitle(e.target.value)} />

      <div
        style={{ background: '#7fbf7f', color: '#ffffff', padding: 6, display: 'inline-block' }}
        onClick={add}
      >
        เพิ่มรายการ
      </div>

      <span onClick={() => setItems([])} style={{ cursor: 'pointer' }}>
        ✕
      </span>

      <ul>
        {items.map(i => (
          <li key={i}>{i}</li>
        ))}
      </ul>

      <img src="logo.png" />
    </div>
  );
};

export default BadForm;

ขั้นตอนการปฏิบัติ

  1. สร้างไฟล์ src/components/BadForm.tsx จากโค้ดตั้งต้น เขียนไฟล์ทดสอบ BadForm.test.tsx ที่ค้นหาด้วย getByRole('heading', ...), getByLabelText(...), getByRole('button', { name: ... }) 2 ปุ่ม และ getByAltText(...) รันแล้วบันทึกว่ากรณีใดล้มและข้อความว่าอย่างไร (นี่คือหลักฐานของปัญหา)

  2. แก้ BadForm ให้การทดสอบผ่านครบ ด้วยการแก้ปัญหาอย่างน้อย 5 จุดที่ซ่อนอยู่ (แนะนำให้อ่านโค้ดและตารางปัญหาที่พบบ่อยในใบความรู้) สีปุ่มต้องมีอัตราส่วนความต่างอย่างน้อย 4.5 ต่อ 1 (ตรวจด้วยเครื่องมือวัด contrast ของ Chrome DevTools และบันทึกค่าก่อนและหลัง) เขียนตารางสรุป: ปัญหา เหตุผลที่เป็นปัญหา วิธีแก้

  3. สร้างแอปของตนเองเป็นเวอร์ชัน build (npm run build แล้ว npm run preview) รัน Lighthouse โหมด Mobile หมวด Performance, Accessibility, Best practices บันทึกคะแนนและภาพหน้าจอผล

  4. แก้ปัญหาที่ Lighthouse และการทดสอบด้วยแป้นพิมพ์พบในแอปของตนเองอย่างน้อย 5 จุด (เช่น ป้ายชื่อช่องกรอก aria-label ของปุ่มไอคอน contrast ลำดับโฟกัส) แล้ววัด Lighthouse ซ้ำ บันทึกคะแนนก่อนและหลัง

  5. ทดสอบด้วยแป้นพิมพ์: ใช้ Tab ผ่านทุกฟังก์ชันของ use case หลัก 2 ข้อโดยไม่ใช้เมาส์ บันทึกปัญหาที่พบ ทดสอบกับโปรแกรมอ่านหน้าจอ (TalkBack, VoiceOver หรือ NVDA อย่างใดอย่างหนึ่ง) บันทึกสิ่งที่ได้ยินและปัญหา ถ้าไม่มีเครื่องมือให้ระบุว่าไม่ได้ทดสอบ และเหตุผล

  6. ประเมินคุณภาพตามคุณลักษณะของ ISO/IEC 25010:2023 ครบ 9 ข้อ ในรูปตาราง: คุณลักษณะ คำถามที่ใช้ผลการประเมิน (ดี/พอใช้/ต้องปรับปรุง) หลักฐาน (ผลทดสอบ คะแนน ภาพ) และข้อเสนอแนะ

  7. ให้เพื่อน 2 คนลองใช้แอปทำงานหลัก 1 งานโดยไม่ได้รับคำอธิบาย สังเกตและบันทึกจุดที่ติดขัดโดยเทียบกับหลักการของ Nielsen อย่างน้อย 3 ข้อ

  8. เขียนแผนปรับปรุง 5 ข้อเรียงตามความสำคัญ (ปัญหา ผลกระทบ วิธีแก้ ผู้รับผิดชอบ เวลา)

คำแนะนำ

  • ถ้า getByRole หาปุ่มไม่เจอ ให้ดูข้อความผิดพลาดของ Testing Library ซึ่งแสดงรายการบทบาทที่มีอยู่จริงในหน้า
  • สีขาวบนสีเขียวอ่อนมักไม่ผ่าน 4.5 ต่อ 1 ลองใช้สีที่เข้มขึ้นและวัดค่าใหม่
  • คะแนน Lighthouse เปลี่ยนได้ตามแต่ละรอบ ให้วัด 3 รอบแล้วบันทึกค่ากลาง
  • ถ้าแอปใช้ Ionic หน้านั้นตรวจด้วย Testing Library ไม่ได้ครบ ให้เน้น Lighthouse และการทดสอบด้วยมือ
  • ไฟล์ index.html ของโปรเจกต์ที่สร้างจาก ionic start ตั้งค่า viewport เป็น maximum-scale=1.0 และ user-scalable=no ซึ่งปิดการซูมของผู้ใช้ ผู้ที่สายตาไม่ดีใช้งานลำบาก Lighthouse จะเตือนข้อนี้ ให้พิจารณาลบสองค่านี้ออกแล้ววัดซ้ำ (ตรวจว่าหน้าจอยังแสดงถูกต้องหลังซูมได้)

สิ่งที่ต้องส่ง

ลิงก์ GitHub + ตารางสรุปการแก้ BadForm พร้อมผลทดสอบก่อน-หลัง + คะแนน Lighthouse ก่อน-หลัง + ตารางประเมิน ISO/IEC 25010 + บันทึกการทดสอบแป้นพิมพ์/โปรแกรมอ่านหน้าจอ + บันทึกการสังเกตผู้ใช้ + แผนปรับปรุง (ส่งตามช่องทางที่ครูกำหนด)
