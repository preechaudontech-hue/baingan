ใบงานที่ 2.3 Class Diagram และข้อมูลของแอป

เวลา 120 นาที · งานเดี่ยว · คะแนนเต็ม 10

จุดประสงค์

วาด Class Diagram ขั้นต้นของแอปตนเอง และสร้างตัวอย่างข้อมูล JSON ที่ตรงกับคลาส

คำชี้แจง

ใช้ use case จากใบงาน 2.2 หาข้อมูลที่แอปต้องเก็บ แล้วออกแบบเป็นคลาส ตัวอย่างคือคลาส Expense ของ MyExpense ผลงานนี้จะถูกใช้อีกครั้งในหน่วยที่ 6 (ฐานข้อมูล) และ 7 (API) ทำทีละขั้นให้ครบก่อนเริ่มวาดภาพ

สิ่งที่ต้องเตรียม

  • ผลงานใบงาน 2.1 และ 2.2
  • ใบความรู้ที่ 2 หัวข้อ Class Diagram

ขั้นตอนการปฏิบัติ

  1. เปิดรายการ use case จากใบงาน 2.2 แล้วขีดเส้นใต้ คำนาม ในชื่อและขั้นตอนของแต่ละอัน (เช่น รายจ่าย หมวดหมู่ เดือน)

    ผลที่ควรเห็น: ได้คำนามที่ถูกขีดเส้นใต้ในทุก use case

  2. คัดคำนามที่ไม่ซ้ำกันออกมาเป็นรายการ แล้วตัดทิ้งคำที่ไม่ใช่ข้อมูลที่ต้องเก็บ (เช่น หน้าจอ ปุ่ม)

    ผลที่ควรเห็น: ได้รายการ เช่น รายจ่าย หมวดหมู่ ผู้ใช้

  3. ตั้งชื่อคลาสจากรายการ ใช้ภาษาอังกฤษตัวแรกพิมพ์ใหญ่ เอกพจน์ อย่างน้อย 3 คลาส

    ผลที่ควรเห็น: ได้ชื่อ เช่น User, Expense, Category

  4. ถ้าได้ไม่ถึง 3 คลาส ให้คิดต่อว่ามีข้อมูลสนับสนุนอะไรอีก (เช่น หมวดหมู่ การตั้งค่า เป้าหมาย) แล้วเพิ่มจนครบ 3 คลาส

    ผลที่ควรเห็น: มีอย่างน้อย 3 ชื่อคลาส

  5. วาดกล่อง 3 ส่วนของคลาสแรก: ชื่อคลาส (ส่วนบน) คุณสมบัติ (ส่วนกลาง) พฤติกรรม (ส่วนล่าง) ยังไม่ต้องเขียนรายละเอียด

    ผลที่ควรเห็น: ได้กล่องที่แบ่ง 3 ส่วนและมีชื่อคลาส

  6. เขียนคุณสมบัติ id ของคลาสแรกเป็นบรรทัดแรก ในรูปแบบ - id : int (เครื่องหมาย - คือ private)

    ผลที่ควรเห็น: ได้บรรทัด - id : int

  7. เขียนคุณสมบัติที่เหลือของคลาสแรกทีละบรรทัด โดยมีชนิดข้อมูลกำกับ เช่น - title : String, - amount : double, - category : String, - date : Date

    ผลที่ควรเห็น: ทุกบรรทัดมีรูปแบบ ชื่อ : ชนิด

  8. ทำแบบเดียวกันกับคลาสที่ 2 และ 3 (ใส่ id เป็นบรรทัดแรกทุกคลาส)

    ผลที่ควรเห็น: ทุกคลาสมี id และชนิดข้อมูลครบทุกบรรทัด

  9. เขียนพฤติกรรมของแต่ละคลาสอย่างน้อย 1 รายการในส่วนล่างของกล่อง ในรูปแบบ + ชื่อ() : ชนิดที่คืน เช่น + validate() : boolean ถ้าคลาสใดไม่มีพฤติกรรม ให้เขียนเหตุผลสั้น ๆ ข้างกล่อง

    ผลที่ควรเห็น: ทุกคลาสมีพฤติกรรมอย่างน้อย 1 รายการ หรือมีเหตุผลที่ไม่มี

  10. ถามคู่คลาสทีละคู่ว่า เกี่ยวข้องกันไหม เช่น User กับ Expense, Category กับ Expense แล้วลากเส้นเชื่อมคู่ที่เกี่ยวข้อง

    ผลที่ควรเห็น: ทุกคลาสมีเส้นเชื่อมอย่างน้อย 1 เส้น

  11. เลือกชนิดความสัมพันธ์ของแต่ละเส้นโดยตอบ: ส่วนย่อยอยู่ได้เองเมื่อไม่มีส่วนรวมหรือไม่ ถ้าอยู่ได้ให้เป็น Association หรือ Aggregation (ข้างส่วนรวมมีสัญลักษณ์ข้าวหลามตัดโปร่ง) ถ้าหายตามให้เป็น Composition (ข้าวหลามตัดทึบ) ถ้าเป็นการสืบทอดให้เป็น Generalization (ลูกศรหัวสามเหลี่ยมโปร่ง)

    ผลที่ควรเห็น: ทุกเส้นมีชนิดกำกับหรือสัญลักษณ์ปลายเส้นที่ถูกต้อง

  12. เขียน multiplicity ที่ปลายเส้นทั้งสองข้างของทุกเส้น ใช้ 1, 0..1, 0..* หรือ 1..* โดยอ่านเป็นประโยคทวนว่าถูกต้อง เช่น User 1 คนมี Expense ได้ 0 ถึงหลายรายการ

    ผลที่ควรเห็น: ทุกปลายเส้นมีตัวเลขหรือสัญลักษณ์จำนวน

  13. บันทึกหรือถ่ายภาพ Class Diagram (ถ้าวาดในโปรแกรม ใช้เมนู File แล้ว Export as เลือก PNG)

    ผลที่ควรเห็น: ได้ภาพที่อ่านคุณสมบัติและตัวเลขได้ชัด

  14. ทำตารางคุณสมบัติของคลาสแรก (ชื่อ / ชนิด / ความหมาย / ตัวอย่างค่า) ในไฟล์ Word

    ผลที่ควรเห็น: ได้ตารางครบทุกคุณสมบัติของคลาสแรก

  15. ทำตารางคุณสมบัติของคลาสที่ 2 และ 3

    ผลที่ควรเห็น: ตารางครบทั้ง 3 คลาส

  16. เขียนตัวอย่างข้อมูลจริงของคลาสแรก 1 รายการเป็น JSON โดยชื่อคีย์ตรงกับชื่อคุณสมบัติ ใช้เครื่องหมาย " คร่อมชื่อและค่าที่เป็นข้อความ ตัวเลขไม่ต้องคร่อม และไม่มีเครื่องหมายจุลภาคเกินท้ายสุด ตัวอย่าง: {"id": 1, "title": "ข้าวกลางวัน", "amount": 45, "category": "อาหาร", "date": "2569-10-27"}

    ผลที่ควรเห็น: ได้ JSON 1 รายการ 1 ออบเจ็กต์

  17. เขียนตัวอย่างรายการที่ 2 ของคลาสแรกที่ใช้ค่าต่างจากรายการแรก

    ผลที่ควรเห็น: ได้ 2 รายการของคลาสแรก

  18. เขียนตัวอย่างข้อมูล 2 รายการของคลาสที่ 2 และ 3

    ผลที่ควรเห็น: ได้ครบ 6 รายการ (3 คลาส คลาสละ 2)

  19. ตรวจรูปแบบ JSON: เปิดเว็บตรวจ JSON ออนไลน์ (ค้นหาคำว่า JSON validator) วางข้อมูลของแต่ละคลาส (ห่อ 2 รายการด้วย [ ] เพื่อให้เป็นอาเรย์) แล้วกดตรวจ หรือให้เพื่อนอ่านตรวจ ห้ามวางข้อมูลส่วนตัวจริงลงเว็บ

    ผลที่ควรเห็น: เว็บแจ้งว่า Valid JSON (ถ้าแจ้งผิด ให้ดูตำแหน่งที่แจ้งแล้วแก้ เช่น ลืมเครื่องหมายคำพูดหรือจุลภาค)

  20. เปิดผลงาน 2.2 เลือก use case เพิ่มรายจ่าย แล้วเขียนรายการข้อมูลที่หน้าจอต้องรับจากผู้ใช้ทีละช่อง

    ผลที่ควรเห็น: ได้รายการช่อง เช่น ชื่อรายการ จำนวนเงิน หมวดหมู่ วันที่

  21. เทียบทีละช่องกับคุณสมบัติของคลาส ถ้าช่องใดไม่มีคุณสมบัติรองรับ ให้เพิ่มคุณสมบัติ และถ้าคุณสมบัติใดไม่มีช่องที่ใช้ ให้พิจารณาว่าจำเป็นหรือไม่

    ผลที่ควรเห็น: ทุกช่องมีคุณสมบัติรองรับ

  22. ทำแบบเดียวกันกับ use case ที่แสดงข้อมูล (เช่น ดูรายการรายจ่าย ดูสรุป) แล้วบันทึกข้อสังเกตที่พบเป็นข้อความ 2-3 บรรทัด

    ผลที่ควรเห็น: ได้ข้อสังเกต เช่น ต้องเพิ่มคุณสมบัติ month เพื่อสรุปรายเดือน

  23. แก้ภาพ Class Diagram และตาราง ตามข้อสังเกต แล้วรวมเป็นไฟล์เดียว (ภาพ ตารางคุณสมบัติ ตัวอย่าง JSON) ส่งตามช่องทางที่ครูกำหนด

    ผลที่ควรเห็น: ไฟล์ส่งงานมี 3 ส่วนและตรงกัน

คำแนะนำ

  • คุณสมบัติ id ควรมีทุกคลาส เพื่อระบุแต่ละรายการได้ ใช้ต่อในฐานข้อมูลหน่วยที่ 6
  • ชื่อคีย์ใน JSON ควรตรงกับชื่อคุณสมบัติในคลาส เพื่อไม่ต้องแปลงชื่อภายหลัง
  • ถ้าไม่แน่ใจ multiplicity ให้เล่าเป็นประโยค เช่น Category 1 หมวดมี Expense ได้ 0 ถึงหลายรายการ แล้วค่อยแปลงเป็น 0..*

สิ่งที่ต้องส่ง

ภาพ Class Diagram + ตารางคุณสมบัติของแต่ละคลาส + ตัวอย่างข้อมูล JSON ของแต่ละคลาส
