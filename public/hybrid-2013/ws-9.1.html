ใบงานที่ 9.1 ตรวจความพร้อมและเผยแพร่แอปเป็นเว็บแอป

เวลา 120 นาที · งานเดี่ยว · คะแนนเต็ม 10

จุดประสงค์

ตรวจความพร้อมของแอปก่อนเผยแพร่ build และเผยแพร่เป็นเว็บแอปแบบ HTTPS และเตรียมข้อมูลประกอบการเผยแพร่ได้ครบถ้วน

คำชี้แจง

ใบงานนี้ทำกับแอปของตนเองจากหน่วยที่ 4 - 8 ทำทีละขั้นตามลำดับ ขั้นที่เมนูของบริการโฮสติ้งอาจเปลี่ยนตามเวลา ให้ยึดชื่อเมนูตามที่หน้าเว็บแสดงจริง และถ้าต่างจากใบงานให้ถามครู

สิ่งที่ต้องเตรียม

  • ผลงานแอปของตนเองจากหน่วยที่ 4 - 8
  • ใบความรู้ที่ 9
  • บัญชี GitHub และบัญชีของบริการโฮสติ้งที่ครูกำหนด

ขั้นตอนการปฏิบัติ

  1. เปิดไฟล์ Word ใหม่ ทำตารางรายการตรวจสอบ 4 คอลัมน์ (หมวด / รายการตรวจ / ผล ผ่านหรือไม่ผ่าน / หลักฐาน) ตามหมวดในใบความรู้: ฟังก์ชัน ทดสอบ คุณภาพ ความปลอดภัย สิทธิ์ ข้อมูลทดสอบ ข้อมูลประกอบ ลิขสิทธิ์ คู่มือ รวมอย่างน้อย 12 ข้อ

    ผลที่ควรเห็น: ได้ตารางเปล่าที่มีอย่างน้อย 12 แถว

  2. ตรวจรายข้อและกรอกผล: ข้อ ฟังก์ชัน ให้ลองทำ use case ระดับ Must ในแอปทีละข้อ ข้อ ทดสอบ ให้รันคำสั่งด้านล่าง

    npm run test:unit
    ผลที่ควรเห็น: ท้ายจอขึ้น Tests N passed (N) ไม่มีข้อที่ failed ถ่ายภาพใส่ช่องหลักฐาน

  3. ตรวจ Console: เปิดแอปในเบราว์เซอร์ กด F12 แท็บ Console แล้วใช้แอปทำ use case หลัก

    ผลที่ควรเห็น: ไม่มีข้อความสีแดง ถ้ามีให้จดไว้เป็นข้อที่ไม่ผ่าน

  4. ตรวจกุญแจลับในโค้ด: ค้นหาคำเหล่านี้ทั้งโปรเจกต์ใน VS Code (กด Ctrl+Shift+F): password, secret, apikey, token, key=

    ผลที่ควรเห็น: ไม่พบรหัสผ่านหรือกุญแจจริงในโค้ด (ถ้าพบ ให้ย้ายออกจากโค้ดและเปลี่ยนรหัสนั้นทันที เพราะถือว่ารั่วแล้ว)

  5. ตรวจประวัติ Git ว่าเคยอัปโหลดไฟล์ลับหรือไม่ รันคำสั่งนี้ใน Git Bash (หรือเทอร์มินัลของ VS Code ที่เลือกเป็น Git Bash) แล้วดูรายชื่อไฟล์

    git log --all --name-only --pretty=format: | sort -u | grep -i "env\|key\|secret\|keystore"
    ผลที่ควรเห็น: ไม่มีรายชื่อไฟล์ใดแสดงออกมา (ถ้ามี แจ้งครูก่อนทำต่อ)

  6. เปิดไฟล์ .gitignore ตรวจว่ามีบรรทัด .env (และ *.keystore ถ้ามี) อยู่ ถ้าไม่มี ให้เพิ่มบรรทัดเหล่านั้นไว้ท้ายไฟล์ แล้วบันทึก

    ผลที่ควรเห็น: ไฟล์ .gitignore มีบรรทัด .env

  7. แก้ข้อที่ไม่ผ่านอย่างน้อย 3 ข้อ (เช่น ลบ console.log ที่ไม่จำเป็น ลบข้อมูลทดสอบ แก้การเข้าถึงตามใบงาน 8.2) แล้วบันทึกว่าแก้อะไรและหลักฐานก่อนหลัง

    ผลที่ควรเห็น: มีรายการแก้ไข 3 ข้อในตาราง

  8. สร้างเวอร์ชัน build

    npm run build
    ผลที่ควรเห็น: บรรทัดท้ายขึ้น built in ... วินาที ไม่มีข้อความ error (ข้อความสีเหลืองเรื่อง chunks are larger than 500 kB เป็นคำเตือน ไม่ใช่ข้อผิดพลาด) จะได้โฟลเดอร์ dist

  9. ดูขนาดไฟล์จากผลของ npm run build ในรายการแต่ละไฟล์ (เช่น dist/assets/index-xxxx.js) บันทึกขนาดไฟล์ที่ใหญ่ที่สุด 3 ไฟล์ลงตาราง

    ผลที่ควรเห็น: ได้ขนาด 3 ไฟล์ (หน่วย kB)

  10. เปิดดูเวอร์ชัน build ในเครื่อง

    npm run preview
    ผลที่ควรเห็น: ขึ้น Local: http://localhost:4173/ (พอร์ตอาจต่างกัน) เปิดที่อยู่นี้ในเบราว์เซอร์ จะเห็นแอปเหมือนตอนพัฒนา

  11. ทดสอบลิงก์ลึก: ในเบราว์เซอร์พิมพ์ที่อยู่ตามด้วย /item/1 (หรือเส้นทางอื่นของแอปคุณ) แล้วกด Enter จากนั้นกด F5 รีเฟรช

    ผลที่ควรเห็น: หน้านั้นเปิดได้ ไม่ขึ้น 404 (เพราะ vite preview ตอบ index.html ให้ทุกเส้นทาง) ถ้าเส้นทางที่ไม่มีในแอปจะแสดงตามที่แอปกำหนด

  12. กด Ctrl+C ที่เทอร์มินัลเพื่อหยุด preview แล้วส่งโค้ดขึ้น GitHub

    git add .
git commit -m "prepare release"
git push
    ผลที่ควรเห็น: ขึ้น Writing objects ... done

  13. เผยแพร่เป็นเว็บแอป: เข้าบริการโฮสติ้งที่ครูกำหนด (เช่น Render) สร้างเว็บแบบ Static Site เลือกที่เก็บ GitHub ของคุณ ตั้งค่า Build Command เป็น npm install && npm run build และ Publish Directory เป็น dist แล้วกดสร้าง (ชื่อเมนูของบริการเปลี่ยนได้ ถ้าไม่ตรงให้ถามครู)

    ผลที่ควรเห็น: หน้าสถานะการ deploy ขึ้น Live หรือคำที่มีความหมายว่าสำเร็จ และมีลิงก์เว็บ (รอบแรกใช้เวลาหลายนาที)

  14. ตั้งค่า SPA fallback ในหน้าตั้งค่าของบริการ: เพิ่มกฎ rewrite จากเส้นทาง /* ไปที่ /index.html (บน Render อยู่ในเมนู Redirects/Rewrites เลือก Action เป็น Rewrite) ถ้าเป็นบริการอื่น ให้ค้นหาคำว่า SPA fallback ในเอกสารของบริการนั้น

    ผลที่ควรเห็น: บันทึกกฎแล้ว ขั้นตอนนี้ยังไม่ได้ทดสอบกับทุกบริการ ให้ตรวจผลในขั้นถัดไป

  15. เปิดลิงก์เว็บจริงบนมือถือ ทดสอบ use case หลัก แล้วเปิดลิงก์ลึก (เช่น ลิงก์ที่ลงท้าย /item/1) และรีเฟรช

    ผลที่ควรเห็น: แอปเปิดและใช้งานได้ ลิงก์ลึกไม่ขึ้น 404 หลังรีเฟรช ถ่ายภาพหน้าจอมือถือพร้อมแถบที่อยู่เว็บ (ถ้าขึ้น 404 แปลว่ากฎ rewrite ยังไม่ทำงาน ตรวจขั้นก่อนหน้า)

  16. ตั้งค่าไฟล์ capacitor.config.ts ของโปรเจกต์: ถ้ามีไฟล์อยู่แล้ว ให้เปิดดู ถ้ายังไม่มี ให้สร้างที่ราก ของโปรเจกต์ (โฟลเดอร์เดียวกับ package.json) วางโค้ดนี้ทั้งไฟล์ กด Ctrl+S

    ไฟล์ capacitor.config.ts
    import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  // TODO: appId เป็นชื่อแบบโดเมนกลับด้าน ต้องไม่ซ้ำกับแอปอื่น และเปลี่ยนไม่ได้เมื่อเผยแพร่บนร้านแอป
  // ใช้โดเมนหรือบัญชีของตนเอง เช่น io.github.ชื่อผู้ใช้ของคุณ.myexpense (ภาษาอังกฤษพิมพ์เล็ก ไม่มีช่องว่าง)
  appId: 'io.github.yourname.myexpense',

  // TODO: ชื่อแอปที่ผู้ใช้เห็นใต้ไอคอน
  appName: 'MyExpense',

  // โฟลเดอร์ผลลัพธ์ของ npm run build (Vite ใช้ dist)
  webDir: 'dist',
};

export default config;
    ผลที่ควรเห็น: ไม่มีข้อความแดง (ตัวแก้ไขอาจขีดเส้นใต้ใน import ถ้ายังไม่ได้ติดตั้ง @capacitor/cli ให้ข้ามได้ถ้าโปรเจกต์มี Capacitor อยู่แล้ว)

  17. แก้ appId ให้เป็นรหัสของคุณเอง (ตัวพิมพ์เล็กภาษาอังกฤษ ไม่มีช่องว่าง รูปแบบโดเมนกลับด้าน) แทนบรรทัด appId เดิม (ตัวอย่างใช้ชื่อ somchai แทนชื่อผู้ใช้ GitHub ของคุณ)

    ไฟล์ capacitor.config.ts
    appId: 'io.github.somchai.myexpense',
    ผลที่ควรเห็น: ไม่มีข้อความแดง ห้ามเว้นวรรคหรือใช้ตัวพิมพ์ใหญ่ เพราะ appId เปลี่ยนไม่ได้หลังเผยแพร่บนร้านแอป

  18. แก้ appName เป็นชื่อแอปที่ผู้ใช้เห็นใต้ไอคอน

    ไฟล์ capacitor.config.ts
    appName: 'รายจ่ายของฉัน',
    ผลที่ควรเห็น: ไม่มีข้อความแดง

  19. ลบบรรทัดคอมเมนต์ TODO ที่ทำเสร็จแล้ว (ไม่บังคับ) แล้วบันทึก

    ผลที่ควรเห็น: ไฟล์เหลือ 3 ค่า: appId appName webDir

  20. เตรียมภาพต้นฉบับของไอคอน: สร้างโฟลเดอร์ assets ที่รากโปรเจกต์ (ถ้ายังไม่มี) ใส่ไฟล์ icon-only.png ขนาด 1024 x 1024 พิกเซล และ splash.png (ภาพสี่เหลี่ยมจัตุรัสใหญ่ ตัวสัญลักษณ์อยู่ตรงกลาง ไม่ชิดขอบ)

    ผลที่ควรเห็น: มีไฟล์ assets/icon-only.png และ assets/splash.png

  21. เตรียมข้อมูลประกอบในเอกสาร Word เดียว: ชื่อและรหัสแอป คำอธิบายสั้น (บรรทัดเดียว) คำอธิบายยาว ภาพหน้าจอ 3 ภาพ ตารางสิทธิ์ที่ขอและเหตุผล กลุ่มผู้ใช้เป้าหมาย และรายการอ้างอิง (API ไลบรารี รูปภาพ)

    ผลที่ควรเห็น: ได้เอกสาร 1 ไฟล์ครบ 6 หัวข้อ

  22. เขียนนโยบายความเป็นส่วนตัวอย่างน้อย 1 หน้า ใต้หัวข้อ: ข้อมูลที่เก็บ ข้อมูลที่ส่งออกไปยัง API ที่เก็บข้อมูลอยู่ที่ใด สิทธิ์ของผู้ใช้ ช่องทางติดต่อ (หัวข้อเหล่านี้ตรวจจากแอปจริงของคุณ เช่น ข้อมูลอยู่ในเครื่องหรือไม่ ส่งชื่อเมืองไป Open-Meteo หรือไม่)

    ผลที่ควรเห็น: ได้นโยบาย 1 หน้า ที่ตรงกับพฤติกรรมจริงของแอป

  23. นำนโยบายขึ้นให้ผู้ใช้เห็น: อย่างน้อยเป็นหน้า เกี่ยวกับ ในแอป (สร้างเป็นหน้าใหม่ตามวิธีในใบงาน 4.4) หรือเป็นหน้าเว็บ แล้วเพิ่มลิงก์ไปหน้านี้ในหน้าหลัก

    ผลที่ควรเห็น: กดลิงก์ในแอปแล้วเห็นนโยบาย

  24. กำหนดเวอร์ชัน: เปิดไฟล์ package.json แก้บรรทัด "version" เป็น 1.0.0 แล้วบันทึก

    ผลที่ควรเห็น: ในไฟล์เห็น "version": "1.0.0",

  25. สร้างไฟล์ CHANGELOG.md ที่รากโปรเจกต์ วางเนื้อหานี้ (แก้ข้อความให้ตรงกับแอปของคุณ) บันทึก

    ไฟล์ CHANGELOG.md
    # บันทึกการเปลี่ยนแปลง

## 1.0.0

- เพิ่มหน้าจอบันทึกรายจ่ายและดูรายการ
- เพิ่มการค้นหาและลบรายการ
- เก็บข้อมูลไว้ในเครื่อง ไม่ต้องต่ออินเทอร์เน็ต
    ผลที่ควรเห็น: มีไฟล์ CHANGELOG.md ที่ตรงกับความสามารถจริงของแอป

  26. ส่งขึ้น GitHub พร้อมติดแท็กเวอร์ชัน

    git add .
git commit -m "release 1.0.0"
git tag v1.0.0
git push
git push origin v1.0.0
    ผลที่ควรเห็น: ขึ้น Writing objects ... done และ * [new tag] v1.0.0 -> v1.0.0 ที่หน้า GitHub มีแท็ก v1.0.0 ในเมนู Tags

  27. ขั้นเสริม (เฉพาะเครื่องที่พร้อม: Node.js 22 ขึ้นไป Android Studio JDK 21) สร้างโปรเจกต์ Android: รันคำสั่งทีละบรรทัดตามลำดับ

    npm install @capacitor/android
npm run build
npx cap add android
npx cap sync
    ผลที่ควรเห็น: เกิดโฟลเดอร์ android ในโปรเจกต์ ถ้า Node ต่ำกว่า 22 จะขึ้นข้อความแจ้งเวอร์ชัน ให้อัปเกรดก่อน (ขั้นนี้ไม่ได้ทดสอบบนเครื่องของผู้เขียนใบงานจนจบถึงติดตั้งบนมือถือ)

  28. ขั้นเสริม สร้างไอคอนทุกขนาด (ต้องมีโฟลเดอร์ android แล้ว)

    npm install -D @capacitor/assets
npx capacitor-assets generate --android
    ผลที่ควรเห็น: เครื่องมือรายงานจำนวนไฟล์ภาพที่สร้างใน android/app/src/main/res บันทึกผลที่ได้

  29. ขั้นเสริม เปิดโปรเจกต์ใน Android Studio แล้วตรวจไฟล์ android/app/src/main/AndroidManifest.xml ว่าสิทธิ์ที่มีตรงกับตารางสิทธิ์ของคุณ (ค่าเริ่มต้นมีเพียง INTERNET)

    npx cap open android
    ผลที่ควรเห็น: Android Studio เปิดโปรเจกต์ได้ (รอ Gradle sync ครั้งแรกหลายนาที) ถ้าเครื่องยังไม่พร้อม ให้เขียนในรายงานว่า ยังไม่ได้ทดสอบ และแผนว่าจะทำเมื่อใด

คำแนะนำ

  • ถ้าลิงก์ลึกขึ้น 404 บนเว็บที่เผยแพร่ ให้เพิ่มกฎ rewrite ทุกเส้นทางไป /index.html ตามเอกสารของบริการ
  • ห้ามอัปโหลดไฟล์ keystore ไฟล์ .env หรือรหัสผ่านขึ้น GitHub ตรวจไฟล์ .gitignore ก่อนทุกครั้ง
  • ไอคอนต้นฉบับควรเป็นภาพสี่เหลี่ยมจัตุรัสขนาดใหญ่ ตัวอักษรหรือสัญลักษณ์ควรอยู่ตรงกลาง ไม่ชิดขอบ เพราะบางเครื่องตัดมุมหรือขอบ
  • appId เปลี่ยนไม่ได้หลังเผยแพร่บนร้านแอป ตั้งให้ถูกตั้งแต่ต้นและใช้ตัวพิมพ์เล็กภาษาอังกฤษ

ลิงก์ GitHub + ลิงก์เว็บแอปที่เผยแพร่ + รายการตรวจสอบก่อนเผยแพร่ + ภาพการทดสอบลิงก์ลึกบนมือถือ + เอกสารข้อมูลประกอบ + นโยบายความเป็นส่วนตัว + CHANGELOG.md และแท็กเวอร์ชัน + บันทึกขั้นเสริม (ถ้าทำ) (ส่งตามช่องทางที่ครูกำหนด)
