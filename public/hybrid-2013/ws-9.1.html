ใบงานที่ 9.1 ตรวจความพร้อมและเผยแพร่แอปเป็นเว็บแอป

เวลา 120 นาที · งานเดี่ยว · คะแนนเต็ม 10

จุดประสงค์

ตรวจความพร้อมของแอปก่อนเผยแพร่ build และเผยแพร่เป็นเว็บแอปแบบ HTTPS และเตรียมข้อมูลประกอบการเผยแพร่ได้ครบถ้วน

คำชี้แจง

ตรวจความพร้อมของแอปของตนเองตามรายการตรวจสอบในใบความรู้ แก้ไขสิ่งที่ยังไม่ผ่าน แล้วเผยแพร่เป็นเว็บแอป เตรียมไอคอน นโยบายความเป็นส่วนตัว ตารางสิทธิ์ เวอร์ชัน และบันทึกการเปลี่ยนแปลง ขั้นตอนสร้างแอป Android เป็นขั้นเสริมสำหรับผู้ที่เครื่องพร้อม

สิ่งที่ต้องเตรียม

  • ผลงานแอปของตนเองจากหน่วยที่ 4 - 8
  • ใบความรู้ที่ 9
  • บัญชี GitHub และบัญชีของบริการโฮสติ้งที่ครูกำหนด

โค้ดตั้งต้น

คัดลอกไปวางในไฟล์ที่ระบุในโค้ด
import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  // TODO: appId เป็นชื่อแบบโดเมนกลับด้าน ต้องไม่ซ้ำกับแอปอื่น และเปลี่ยนไม่ได้เมื่อเผยแพร่บนร้านแอป
  // ใช้โดเมนหรือบัญชีของตนเอง เช่น io.github.ชื่อผู้ใช้ของคุณ.myexpense (ภาษาอังกฤษพิมพ์เล็ก ไม่มีช่องว่าง)
  appId: 'io.github.yourname.myexpense',

  // TODO: ชื่อแอปที่ผู้ใช้เห็นใต้ไอคอน
  appName: 'MyExpense',

  // โฟลเดอร์ผลลัพธ์ของ npm run build (Vite ใช้ dist)
  webDir: 'dist',
};

export default config;

ขั้นตอนการปฏิบัติ

  1. ทำรายการตรวจสอบก่อนเผยแพร่ของแอปตนเองเป็นตาราง (หมวด รายการตรวจ ผล หลักฐาน) อย่างน้อย 12 ข้อ ตามหมวดในใบความรู้ ประเมินแต่ละข้อว่าผ่านหรือไม่ผ่าน

  2. แก้ไขข้อที่ไม่ผ่านอย่างน้อย 3 ข้อ (เช่น ลบ console.log ที่ไม่จำเป็น ตรวจหากุญแจลับในโค้ดและประวัติ Git ลบข้อมูลทดสอบ แก้การเข้าถึง) แล้วรัน npm run test:unit และ npm run build ให้ผ่านโดยไม่มี error บันทึกขนาดไฟล์ที่ได้จากผลของ npm run build

  3. เปิดดูเวอร์ชัน build ด้วย npm run preview ทดสอบ use case หลัก 2 ข้อ และเปิดลิงก์ลึก (เช่น /item/1) แล้วรีเฟรช

  4. เผยแพร่เป็นเว็บแอปบนบริการโฮสติ้งที่ครูกำหนด (คำสั่ง build npm install && npm run build โฟลเดอร์ dist) ตั้งค่าให้ทุกเส้นทางตอบ index.html (SPA fallback) แล้วเปิดลิงก์จริงบนมือถือ ทดสอบลิงก์ลึกและรีเฟรช ถ่ายภาพ

  5. ตั้งค่าไฟล์ capacitor.config.ts จากโค้ดตั้งต้น (appId ชื่อแอป) และเตรียมภาพต้นฉบับของไอคอนและ splash: assets/icon-only.png (1024 x 1024) และ assets/splash.png ถ้าทำขั้นเสริม (ข้อ 9) จนมีโฟลเดอร์ android แล้ว ให้รัน npx capacitor-assets generate --android และบันทึกผลที่ได้ (ถ้ายังไม่มีโฟลเดอร์ android ให้เตรียมแค่ภาพต้นฉบับ)

  6. เตรียมข้อมูลประกอบเป็นเอกสารหนึ่งไฟล์: ชื่อและรหัสแอป คำอธิบายสั้นและยาว ภาพหน้าจอ 3 ภาพ ตารางสิทธิ์ที่ขอและเหตุผล กลุ่มผู้ใช้เป้าหมาย และรายการอ้างอิง (API ไลบรารี รูปภาพ)

  7. เขียนนโยบายความเป็นส่วนตัวของแอป (ข้อมูลที่เก็บ ข้อมูลที่ส่งออก ที่เก็บ สิทธิ์ของผู้ใช้ ช่องทางติดต่อ) ความยาวอย่างน้อย 1 หน้า และนำไปเผยแพร่เป็นหน้าเว็บ หรืออย่างน้อยเป็นหน้า "เกี่ยวกับ" ในแอป

  8. กำหนดเวอร์ชัน: ตั้งเวอร์ชันใน package.json เป็น 1.0.0 เขียนไฟล์ CHANGELOG.md ของเวอร์ชันนี้ ติดแท็ก Git v1.0.0 และ push ขึ้น GitHub

  9. ขั้นเสริม (เมื่อเครื่องพร้อม: Node.js 22 ขึ้นไป Android Studio JDK 21): รัน npx cap add android, npx cap sync แล้วเปิดด้วย npx cap open android ตรวจ AndroidManifest.xml ว่าต้องเพิ่มสิทธิ์อะไรให้ตรงกับตารางสิทธิ์ ถ้าทำได้ ให้ติดตั้งบนมือถือจริง ทดสอบกล้องหรือตำแหน่ง และบันทึกผล ถ้าเครื่องยังไม่พร้อม ให้ระบุว่ายังไม่ได้ทดสอบและเขียนแผนว่าจะทำเมื่อใด

คำแนะนำ

  • ถ้าลิงก์ลึกขึ้น 404 บนเว็บที่เผยแพร่ ให้เพิ่มกฎ rewrite ทุกเส้นทางไป /index.html ตามเอกสารของบริการ
  • ห้ามอัปโหลดไฟล์ keystore ไฟล์ .env หรือรหัสผ่านขึ้น GitHub ตรวจไฟล์ .gitignore ก่อนทุกครั้ง
  • ไอคอนต้นฉบับควรเป็นภาพสี่เหลี่ยมจัตุรัสขนาดใหญ่ ตัวอักษรหรือสัญลักษณ์ควรอยู่ตรงกลาง ไม่ชิดขอบ เพราะบางเครื่องตัดมุมหรือขอบ
  • appId เปลี่ยนไม่ได้หลังเผยแพร่บนร้านแอป ตั้งให้ถูกตั้งแต่ต้นและใช้ตัวพิมพ์เล็กภาษาอังกฤษ

สิ่งที่ต้องส่ง

ลิงก์ GitHub + ลิงก์เว็บแอปที่เผยแพร่ + รายการตรวจสอบก่อนเผยแพร่ + ภาพการทดสอบลิงก์ลึกบนมือถือ + เอกสารข้อมูลประกอบ + นโยบายความเป็นส่วนตัว + CHANGELOG.md และแท็กเวอร์ชัน + บันทึกขั้นเสริม (ถ้าทำ) (ส่งตามช่องทางที่ครูกำหนด)
