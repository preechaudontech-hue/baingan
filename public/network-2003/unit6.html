31908-2003 การออกแบบและติดตั้งระบบเครือข่ายหน่วยที่ 6
สารบัญหน่วยนี้1. วินิจฉัยปัญหาการเชื่อมต่อขาดหาย2. เครื่องมือหาตำแหน่งสายผิดปกติ3. ออกแบบให้ขยายตัวได้ (Scalable Design)4. วัดประสิทธิภาพก่อนและหลังปรับปรุง5. การทำงานเป็นทีมแบบฝึกหัดท้ายหน่วยใบงานของหน่วยนี้พิมพ์หน้านี้
หน่วยการเรียนรู้ที่ 6

ประยุกต์ใช้งานและปรับปรุง

หน่วยนี้นำทุกอย่างมาประยุกต์ใช้เป็นโครงงานเล็ก ทีมนักเรียนวินิจฉัยปัญหา แก้ไข และปรับปรุงเครือข่ายให้ขยายตัวได้ แล้ววัดผลก่อนและหลังด้วยตัวเลขที่ตรวจสอบได้ ไม่ใช่ความรู้สึก

เมื่อเรียนจบหน่วยนี้ นักเรียนจะ
  • วินิจฉัยปัญหาการเชื่อมต่อเครือข่ายอย่างเป็นระบบ
  • ใช้เครื่องมือหาตำแหน่งสายที่ผิดปกติ
  • ออกแบบเครือข่ายให้รองรับการขยายตัวในอนาคต
  • วัดและเปรียบเทียบประสิทธิภาพก่อนและหลังปรับปรุงด้วย Throughput และ Latency

1. วินิจฉัยปัญหาการเชื่อมต่อขาดหาย

  1. ยืนยันอาการ: ปัญหาเกิดกับเครื่องเดียว หลายเครื่อง หรือทั้งโซน
  2. ถ้าเครื่องเดียว ตรวจสาย พอร์ต และการตั้งค่า IP ของเครื่อง
  3. ถ้าทั้งโซน ตรวจสวิตช์หรือสายหลักของโซนนั้นและบันทึกล่าสุดของอุปกรณ์
  4. ใช้ ping ไล่จากใกล้ไปไกล: เครื่องตัวเอง (127.0.0.1) → เกตเวย์ → อุปกรณ์ในอีกโซน → อินเทอร์เน็ต เพื่อดูว่าขาดที่ใด
  5. ทดสอบสายในตำแหน่งที่สงสัยด้วยเครื่องทดสอบ ถ้ามีเครื่อง Analyzer ที่วัดความยาวถึงจุดผิดพลาดได้ ให้ใช้ระบุตำแหน่ง
  6. แก้ แล้วทดสอบซ้ำ และบันทึกลงรายงาน

2. เครื่องมือหาตำแหน่งสายผิดปกติ

  • Cable Tester พื้นฐาน: บอกว่าสายต่อถูกหรือไม่ (Open Short Miswire)
  • Cable Analyzer/Certifier: วัดคุณสมบัติสายเทียบกับมาตรฐาน และบางรุ่นบอกระยะจากต้นสายถึงจุดผิดพลาดด้วยหลักการสะท้อนสัญญาณ (TDR)
  • Tone Generator และ Probe: ใช้หาปลายสายที่ไม่รู้ว่าเป็นเส้นไหนในมัดสาย

การบำรุงรักษาสาย UTP ที่พบบ่อยคือ เปลี่ยนหัว RJ-45 ที่หลวม จัดสายที่โดนงอหักให้เข้าที่หรือเปลี่ยนเส้น เก็บสายให้พ้นแหล่งไฟฟ้ารบกวน และติดฉลากให้ครบ

3. ออกแบบให้ขยายตัวได้ (Scalable Design)

  • แบ่งชั้นเครือข่าย: แบบ 3 ชั้น คือ Core (แกนกลาง) Distribution (กระจาย) Access (เชื่อมผู้ใช้) เครือข่ายเล็กอาจรวม Core และ Distribution เข้าด้วยกัน
  • เผื่อพอร์ตและช่องใน Rack: เผื่อพอร์ตสวิตช์ 20-30% และเผื่อช่องใน Rack
  • สายหลักเผื่อ: วางสายหลักความเร็วสูงตั้งแต่แรก การเพิ่มภายหลังแพงกว่า
  • แผน IP และ VLAN: จัดช่วง IP เผื่ออนาคต ใช้การตั้งชื่อและหมายเลขที่สม่ำเสมอ
  • เชื่อมต่อสำรอง (Redundancy): จุดสำคัญควรมีเส้นทางสำรอง เช่น สาย Uplink สองเส้น

ข้อดีของการออกแบบเพื่อขยาย: เพิ่มผู้ใช้หรืออุปกรณ์ได้โดยไม่ต้องรื้อระบบ ต้นทุนรวมระยะยาวต่ำกว่า และปัญหาจากการขยายเกิดน้อยลง

4. วัดประสิทธิภาพก่อนและหลังปรับปรุง

ตัวชี้วัดความหมายวัดด้วย
Throughputความเร็วรับส่งข้อมูลจริง (Mbps)iperf3
Latencyเวลาตอบสนองไปกลับ (ms)ping
Packet Lossร้อยละของแพ็กเก็ตที่หายping จำนวนหลายครั้ง หรือผลของ iperf3
Jitterความแปรปรวนของ Latency สำคัญกับเสียงและวิดีโอiperf3 แบบ UDP

ขั้นตอนที่ถูกต้อง: วัดก่อนปรับปรุงด้วยเงื่อนไขเดียวกัน (เวลาเดียวกัน เครื่องเดียวกัน ขนาดข้อมูลเท่ากัน) ทำซ้ำอย่างน้อย 3 ครั้ง ปรับปรุง แล้ววัดหลังด้วยเงื่อนไขเดิม และสรุปด้วยตารางเปรียบเทียบ

5. การทำงานเป็นทีม

  • แบ่งบทบาทชัดเจน เช่น ผู้วัด ผู้ปรับ ผู้บันทึก ผู้รายงาน และสลับกัน
  • ใช้เอกสารกลางเดียวกันบันทึกผล เพื่อไม่ให้ข้อมูลกระจัดกระจาย
  • ตรวจงานกันเองก่อนส่ง (Peer Review)
  • รับผิดชอบเวลาและความปลอดภัยของสมาชิกในกลุ่ม

แบบฝึกหัดท้ายหน่วย

ลองตอบก่อน แล้วค่อยกดดูแนวคำตอบ

ข้อ 1 อธิบายขั้นตอนการตรวจวินิจฉัยเมื่อเกิดปัญหาการเชื่อมต่อเครือข่ายขาดหาย

ดูแนวคำตอบ

ยืนยันอาการและขอบเขต ตรวจสาย พอร์ต และการตั้งค่าที่ใกล้ที่สุด ใช้ ping ไล่จากเครื่องตัวเอง เกตเวย์ ไปจนถึงปลายทางเพื่อหาจุดที่ขาด ทดสอบสายในจุดที่สงสัย แก้ไข ทดสอบซ้ำ และบันทึกผล

ข้อ 2 วิเคราะห์ข้อดีของการออกแบบเครือข่ายแบบรองรับการขยายตัว (Scalability)

ดูแนวคำตอบ

เพิ่มผู้ใช้และอุปกรณ์ได้โดยไม่รื้อระบบ ต้นทุนรวมระยะยาวต่ำกว่าเพราะเดินสายและวางโครงสร้างครั้งเดียว ลดการหยุดให้บริการเวลาขยาย และดูแลง่ายเพราะมีแผน IP และ VLAN ที่เป็นระเบียบ

ข้อ 3 อธิบายวิธีการเปรียบเทียบประสิทธิภาพเครือข่ายก่อนและหลังการปรับปรุงด้วยเครื่องมือทดสอบประสิทธิภาพ

ดูแนวคำตอบ

วัด Throughput ด้วย iperf3 และ Latency กับ Packet Loss ด้วย ping ในเงื่อนไขเดียวกันทั้งก่อนและหลังปรับปรุง ทำซ้ำอย่างน้อย 3 ครั้ง บันทึกค่าเฉลี่ยในตารางเปรียบเทียบและอธิบายสาเหตุของความต่าง

เอกสารอ้างอิง

  • เอกสารคู่มือ iperf3 และคำสั่ง ping ของระบบปฏิบัติการ
  • คู่มือเครื่องทดสอบ/รับรองสายสัญญาณของผู้ผลิตที่ใช้ในห้องปฏิบัติการ
  • หลักการออกแบบเครือข่ายแบบลำดับชั้น (Hierarchical Network Design) จากเอกสารของ Cisco
